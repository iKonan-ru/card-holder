Подписки, которые знают вашу карту

Расширяем Card Holder от хранилища карт до приватного трекера подписок. Ключевое отличие от рынка: приложение уже хранит ваши карты, поэтому умеет связать подписку с конкретной картой — и первым напомнить о ближайшем списании, когда вы открываете приложение.

Offline & зашифровано — данные не покидают устройство Связь подписка ↔ карта — то, чего нет у конкурентов 6 этапов — от навигации до аналитики
01

Рынок и наше место на нём

Рынок трекеров подписок делится на два лагеря. Автоматические (Rocket Money) подключаются к банку и сами находят списания — но требуют доступ к финансовым данным в облаке. Ручные (Bobby, Subby, SubTrack) — приватные, но «слепые»: не знают, какой картой вы платите. Мы играем в лагере ручных приватных трекеров, но снимаем их главное ограничение.

Приложение Модель Как находит подписки Приватность Их слабое место
Rocket Money Автосинк с банком Автоматически из транзакций Данные в облаке Нужен банковский доступ; платно; США-центрично
Bobby Ручной ввод Руками, каталог сервисов Локально Не знает карту; нет умных подсказок
Subby / SubTrack Ручной ввод Руками + напоминания Локально Оторван от реальных карт пользователя
Card Holder Ручной ввод + карты рядом Руками, каталог + привязка к своей карте Зашифровано, offline — (наш ход: карты уже здесь)

Наш ров №1

Связь подписка ↔ карта. Из подписки — прыжок к карте оплаты; из карты — список всех подписок на ней. Ни один трекер так не умеет, потому что у них нет ваших карт.

Наш ров №2

Смена карты. Потеряли или перевыпустили карту — приложение показывает чек-лист подписок, которые нужно перепривязать. Реальная боль, которую больше никто не решает.

Наш ров №3

Приватность как фича. Всё зашифровано AES-GCM и живёт только в браузере. Никакого банковского доступа, никакого облака — то, за что ценят Bobby, но с умом Rocket Money.

02

Что показываем в подписке

Вы перечислили базу — название, логотип, ссылка на управление, привязанная карта, дата/период и сумма с валютой. Вот эта база плюс слой умных полей, собранный из лучших практик рынка и уникальный «карточный» слой.

База — ваш запрос
  • Логотип + название сервиса (каталог или монограмма)
  • Сумма + валюта списания
  • Период: нед. / мес. / кв. / год / произвольный
  • Дата следующего списания
  • Внешняя ссылка на управление подпиской ↗
  • Привязанная карта — внутренняя ссылка на карту
  • Категория сервиса
Умный слой — подсказки рынка
  • Обратный отсчёт: «через 3 дня», с цветом при срочности
  • Нормализация: ₽599/мес → ₽7 188/год
  • Итоги: сколько всего в месяц и в год
  • Статус: активна / пробный / пауза / отменена
  • Пробный период: дата конца + «успеть отменить»
  • «С вами N мес.» и всего потрачено с первой оплаты
  • Изменение цены ↑ и выгода годовой оплаты
  • Напоминание за N дней до списания
Карточный слой — только у нас
  • Маска карты •• 1234 в цвете карты прямо в строке
  • «Подписки на этой карте» — блок на экране карты
  • Сумма на карту: сколько списывается с каждой карты
  • Миграция при смене карты — чек-лист перепривязки
  • Группировка подписок по карте (переиспользуем сортировку карт)

04

Как это ложится на архитектуру

Приложение построено по Feature-Sliced Design, и подписки идеально в неё встают: подписка — это ещё одна зашифрованная сущность рядом с картами. Огромная часть уже готова к переиспользованию — генерик-шифрование записей, слой IndexedDB, паттерн Zustand-стора, модалки, селекты, sort/filter/group.

entities/subscription/types/types.ts
// Чистый лист: без миграций и версий — как вы и просили.
export type TBillingUnit = 'day' | 'week' | 'month' | 'year';
export type TSubStatus = 'active' | 'trial' | 'paused' | 'canceled';

export interface IBillingCycle {
  interval: number;   // 1, 3, …
  unit: TBillingUnit;
}

export interface ISubscription {
  id: string;
  order: number;              // как у карт — для DnD-сортировки
  name: string;
  serviceId?: string;        // каталог → логотип и цвет
  categoryId?: string;
  amount: number;
  currency: string;          // ISO-4217: 'RUB', 'USD'
  billingCycle: IBillingCycle;
  anchorDate: string;        // известная дата списания → считаем график
  status: TSubStatus;
  cardId?: IBankCard['id']; // ← СВЯЗЬ С КАРТОЙ (наш ров)
  manageUrl?: string;        // внешняя ссылка на управление
  reminderDaysBefore?: number;
  trialEndsAt?: string;
  startedAt?: string;        // для «с вами N мес / всего потрачено»
  notes?: string;
  color?: string;             // переопределение цвета
}

Шифрование — бесплатно

В at-rest.ts уже есть генерик encryptRecordFields<T> / decryptRecordFields<T> — им пользуются owners. Для подписок повторяем один-в-один: новый стор, те же AES-GCM записи.

IndexedDB — +1 стор

onupgradeneeded уже дропает и пересоздаёт сторы. Добавляем subscriptions, поднимаем версию 6→7. Никаких миграций — чистый лист, как вы просили.

Sort / Filter / Group — даром

В card-view-store уже есть persist-стор с сортировкой, фильтрами и группами. Обобщаем паттерн — и список подписок получает то же самое почти без кода.

05

Поэтапный план реализации

Шесть этапов, каждый — самостоятельный вертикальный срез с рабочим результатом и критерием приёмки. Порядок снимает риски: сперва структурный сдвиг (навигация), потом данные, потом UI, и только затем «умные» фичи. Детальная разбивка по файлам — в docs/subscriptions/README.md.

ЭТАП 0
Каркас & навигация

Навигационная оболочка

Самое рискованное изменение — первым. Сегодня приложение одностраничное; вводим таб-бар и раскладываем экраны по страницам, ещё без данных подписок.

  • Виджет app-nav — таб-бар (десктоп: боковой рельс/верхние табы)
  • Рефактор main-page → cards-page; пустые subscriptions-page, overview-page
  • Лёгкий стор навигации (Zustand, persist активного таба)
  • FAB и панели переезжают внутрь своих страниц
Готово, когда  переключение табов работает, карты — как раньше, тесты и покрытие зелёные.
ЭТАП 1
Данные & ядро

Модель, хранилище, движок расписаний

Невидимый, но фундаментальный слой. Всё покрыто тестами (планка проекта >90%).

  • Сущность subscription: типы ISubscription, IBillingCycle
  • IndexedDB: стор subscriptions, версия 7, CRUD поверх генерик-шифрования
  • subscriptions-store (Zustand) — зеркало cards-store
  • Чистые функции lib/subscriptions: getNextChargeDate, getUpcomingCharges, toMonthly, toYearly
  • Конфиги services-config + categories-config + ассеты логотипов (по образцу banks-config)
Готово, когда  подписку можно создать/прочитать/обновить/удалить из консоли, даты списаний считаются верно, юнит-тесты зелёные.
ЭТАП 2
CRUD-интерфейс

Список и форма подписки

Первый осязаемый для пользователя результат: подписками можно управлять целиком из UI.

  • subscription-form (модалка add/edit/delete) на паттернах card-form
  • Поля-селекты: карта (из сохранённых), сервис, категория, период, валюта
  • subscription-list + богатая строка subscription-row (лого, маска карты, статус, отсчёт)
  • Пустое состояние + FAB «Добавить подписку»
Готово, когда  пользователь добавляет, редактирует и удаляет подписку, привязывает карту, видит её в списке.
ЭТАП 3
Детали & связи

Экран деталей и двусторонняя связь с картой

Здесь оживает главный дифференциатор — связь подписка ↔ карта в обе стороны.

  • subscription-detail: нормализация цены, «с вами N мес», напоминание, заметки
  • Внешняя ссылка «Управлять ↗» и внутренний переход «Открыть карту»
  • card-subscriptions-link: блок «Подписки на этой карте» + сумма на карту
  • Баннер миграции «Перевыпустили карту? Обновите подписки»
Готово, когда  из подписки открывается карта и наоборот; на карте виден список её подписок и сумма.
ЭТАП 4
Ближайшие списания

Уведомление при входе & таб-бейдж

Ровно то, что вы просили: сводка ближайших списаний на входе. Для offline-PWA v1 — внутриэкранная (без сервера).

  • Виджет upcoming-charges — баннер вверху главной, считается на каждом открытии
  • Красный бейдж-счётчик на табе «Подписки» (как fab-button__indicator)
  • Представление «Календарь / скоро» с цветными метками сервисов
  • Обработка пробных периодов: «успеть отменить до …»
Готово, когда  при открытии видна сводка списаний за N дней с корректными суммами и датами.
ЭТАП 5
Контроль вида & аналитика

Сортировка, фильтры, обзор трат

Обобщаем существующую инфраструктуру вида карт на подписки и добавляем экран «Обзор».

  • Sort / filter / group для подписок (переиспускаем card-view-паттерн)
  • Группировка по категории и по карте
  • overview-page: итоги месяц/год по валютам, траты по категориям, календарь
  • Экспорт/импорт расширяем на подписки (в существующий формат)
Готово, когда  список сортируется/фильтруется/группируется; обзор показывает верные итоги; бэкап включает подписки.
ЭТАП 6
Полировка & расширения

Реальные напоминания и приятные мелочи

Опциональный слой, который выводит продукт за рамки MVP там, где позволяет платформа.

  • OS-напоминания через Notifications API + Service Worker Periodic Sync (где поддерживается)
  • Конвертация валют по локальной обновляемой таблице курсов (без сети по умолчанию)
  • История цен и индикатор подорожания
  • DnD-сортировка подписок (переиспользуем @dnd-kit), i18n-копирайт, покрытие тестами >90%
Готово, когда  включены выбранные расширения без регрессов; сборка, линт, тесты зелёные.
06

Открытые вопросы — с моими рекомендациями

Решения, которые стоит подтвердить до старта. По каждому — дефолт, с которым можно идти уже сейчас.

Навигация: таб-бар или что-то другое?
Рекомендую нижний таб-бар (Карты · Подписки · Обзор): нативно для установленного PWA, масштабируется, на десктопе — боковой рельс.
Напоминания: реальные push или внутри приложения?
v1 — внутри приложения (сводка на входе). Настоящие OS-уведомления в offline-PWA ненадёжны кросс-браузерно — выносим в Этап 6.
Мультивалютность: конвертировать или нет?
v1 — раздельные итоги по валютам (offline, без курсов). Конвертация по локальной таблице — опция Этапа 6.
Категории: фиксированный набор или справочник?
v1 — встроенный набор с иконками/цветами (Развлечения, Музыка, Видео, Облако, Игры, Продуктивность…). Пользовательские — позже, по паттерну owners.
Каталог сервисов: сколько логотипов в v1?
~15–20 популярных (RU + глобальные), остальное — цветная монограмма-фолбэк, как для банков без логотипа.
Подписка без карты — разрешаем?
Да, карта опциональна. Наличная/чужая подписка тоже учитывается; связь с картой — бонус, а не обязанность.
